## 💡 Pro Tips

1. **Always start with understanding** - Spend 1-2 hours on root cause before coding
2. **Use existing patterns** - Reference similar code: "Like X at line Y"
3. **Test thoroughly** - 50-100+ tests prevent regressions
4. **Keep proposals brief** - 500-800 words, plain English
5. **Evaluate alternatives** - Show 3+ approaches, pick the best
6. **Follow the template** - Don't invent your own format
7. **Quality over speed** - 6 hours done right > 2 hours rushed

---

## ⚠️ Red Flags (Stop and Reconsider)

If you're doing any of these, STOP:

- ❌ Writing code before understanding root cause
- ❌ Solution is > 50 lines
- ❌ Only wrote 10-20 tests
- ❌ Proposal has technical jargon
- ❌ Didn't evaluate alternatives
- ❌ Skipped phases in workflow
- ❌ Not referencing existing patterns

**Fix these before proceeding.**
